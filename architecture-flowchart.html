Akamai Early Hints Architecture

Dynamic HTTP 103 Early Hints with EdgeWorkers and EdgeKV

System Architecture

🗄️ EdgeKV
Global key-value storage for dynamic hints. Single all_hints item stores all discovered resources.

Performance: ~3-7ms read latency (measured)
⚡ hints-reader (EW 1)
Fires before cache on HTML requests. Reads EdgeKV, merges with static hints, sets PMUSER variable for HTTP 103 response.

Trigger: onClientRequest
Selective matching: Configure Property Manager to match specific high-value pages (e.g., /home, /products/*, /blog/*). Focus on landing pages and conversion paths—not every page needs early hints.
✍️ hints-updater (EW 2)
Fires after cache miss on specific resource requests. Compares versions, updates EdgeKV if newer, sets cache tags.

Trigger: onOriginResponse
Selective matching: Only fires for specific patterns configured in Property Manager (e.g., ruxitagentjs_*, example.css). Not all files need early hints—only critical resources.
🌐 Origin Server
Returns resources with Last-Modified headers. Only contacted on cache miss. Provides version metadata for update decisions.
🔧 manage-hints.sh
Management script for EdgeKV operations: view hints (--show-content), delete specific key (--delete-key), full reset (--full-reset).
💾 Akamai Cache
Caches resources at edge POPs. EdgeWorkers fire at specific stages: before cache (reader) or after origin response (updater).
🎯 Critical Design Points
  • Before Cache: hints-reader fires on matched HTML requests (client request stage)
  • After Cache: hints-updater fires only on cache misses (origin response stage)
  • Selective Matching: Both EdgeWorkers only fire when explicitly matched in Property Manager—customer controls which paths trigger each EdgeWorker
  • Single EdgeKV Item: One all_hints object eliminates index lookups
  • Version Tracking: Last-Modified headers prevent stale overwrites from cold POPs

EdgeWorker: hints-reader Triggers
onClientRequest event fires (EW 1)

4
EdgeKV Lookup (Single Read)
Read all_hints item from EdgeKV namespace
Performance: ~3-7ms (measured), single lookup for all hints
const allHints = await edgeKV.getJson("all_hints"); // Returns entire hints object: // { // "example.css": { // "filename": "example.css?v=10", // "lastModified": "Wed, 21 Jul 2026 15:30:00 GMT" // }, // ... // }
5
Build Hints String
Merge static hints + dynamic hints from EdgeKV
Format: RFC 8297 Link header format
// Static hints (from config) "<https://fonts.google.com>; rel=preconnect" // Dynamic hints (from EdgeKV) "</example.css?v=10>; rel=preload; as=style" "</app.js?v=5>; rel=preload; as=script" // Combined with ", " delimiter
6
Set PMUSER Variable
EdgeWorker sets PMUSER_103_HINTS variable for Property Manager
request.setVariable( "PMUSER_103_HINTS", allHintsString // Max 8KB );
7
Property Manager: Emit HTTP 103 Early Hints
Property Manager configuration sends HTTP 103 response before final HTML response
HTTP/1.1 103 Early Hints Link: <https://fonts.google.com>; rel=preconnect, </example.css?v=10>; rel=preload; as=style, </app.js?v=5>; rel=preload; as=script
8
Browser Receives Early Hints
Browser starts preloading resources BEFORE HTML arrives
Result: Faster page load, improved Core Web Vitals (LCP)
9
HTML Response Follows
Normal HTTP 200 response with full HTML content
HTTP/1.1 200 OK Content-Type: text/html ... <html>...</html>
⚡ Key Performance Characteristics
  • Single EdgeKV read per HTML page (~3-7ms measured)
  • Total EdgeWorker overhead: ~5ms execution + ~4ms EdgeKV = ~9ms
  • Falls back to static hints on EdgeKV failure (no blocking)
  • Only fires on HTML pages (configured via Property Manager)
  • Hints delivered before HTML parsing begins
1
Resource Request
Browser requests resource: /example.css?v=10
Request arrives at Akamai edge
GET https://example.com/example.css?v=10
2
Property Manager Match Check
CRITICAL: EdgeWorker only fires if matched in Property Manager
Customer configures match criteria:
• Specific patterns: ruxitagentjs_*, example.css
• File types: *.css, *.js, *.woff2
Why selective? Only hint critical resources that benefit from early loading. Not every file needs hints.

If NO MATCH: EdgeWorker will NOT fire → Normal cache/origin flow
If MATCH + Cache HIT: Serve from cache, EdgeWorker will NOT fire
If MATCH + Cache MISS: Proceed to origin → EdgeWorker fires on response
3
Cache Miss → Origin Server
Request forwarded to origin (cache miss + Property Manager match)
4
Origin Server Response
Origin returns resource with metadata
HTTP/1.1 200 OK Last-Modified: Wed, 21 Jul 2026 15:30:00 GMT Cache-Control: public, max-age=31536000 Content-Type: text/css /* CSS content */
5
EdgeWorker: hints-updater Triggers
onOriginResponse event fires (EW 2)
Only fires because:
• Property Manager matched this request (step 2)
• Cache miss occurred (step 3)
• Origin responded (step 4)
async function onOriginResponse(request, response) { // Only process 200 OK responses if (response.status !== 200) return; // Extract filename and version info }
6
Verify Response Status
Check if response is 200 OK
7
Extract Logical Key
Derive logical key by stripping version information
// Examples: "example.css?v=10" → key: "example.css" "ruxitagentjs_ABC_123456.js" → key: "ruxitagentjs" "main.css" → key: "main.css"
8
EdgeKV Read (Check Existing)
Read all_hints to check if key exists and compare versions
const allHints = await edgeKV.getJson("all_hints") || {}; const existingEntry = allHints[logicalKey];
9
Version Comparison
Two-tier comparison to prevent stale writes
9a
Primary: Last-Modified
Compare Last-Modified headers if present
incoming: "Wed, 21 Jul 2026 16:00:00 GMT" existing: "Wed, 21 Jul 2026 15:00:00 GMT" Date.parse(incoming) > Date.parse(existing) → UPDATE
9b
Fallback: Serial Number
Extract version numbers from filename/query
// Query: ?v=202607214303 // Filename: _10329260115094563 BigInt(incomingSerial) > BigInt(existingSerial) → UPDATE BigInt(incomingSerial) <= BigInt(existingSerial) → SKIP (keep existing)
10
Update Decision
UPDATE if: Incoming is newer OR no existing entry
SKIP if: Existing is newer (stale write protection)
11
EdgeKV Write (If Update Required)
Update the all_hints object with new entry
allHints[logicalKey] = { filename: "example.css?v=10", lastModified: "Wed, 21 Jul 2026 15:30:00 GMT" }; await edgeKV.putJson("all_hints", allHints);
12
Set Cache Tags
Add Edge-Cache-Tag header for targeted purging
response.setHeader( "Edge-Cache-Tag", `early-hints,hints-${logicalKey}` ); // Examples: // early-hints,hints-example.css // early-hints,hints-ruxitagentjs
13
Resource Cached & Served
Akamai caches the resource for future requests
Next cache miss will trigger version check again
🛡️ Stale-Write Protection Example
Scenario: Cold edge POP serving old page

1. Current EdgeKV: example.css?v=10
2. Cache miss: example.css?v=08 (from old page reference)
3. Version check: 08 < 10
4. Decision: SKIP - keeps v=10, prevents downgrade

Result: Newest version always preserved
⚡ Performance Characteristics
  • Only fires on cache miss (~3-7ms EdgeKV read + ~3-7ms write = ~10ms total measured)
  • Only updates if incoming version is newer
  • Single EdgeKV item update (atomic operation)
  • EdgeKV propagates globally in ~10 seconds

Show All Hints

Operation 2: Delete Specific Key

2
Delete Single Hint
Remove specific key from EdgeKV and purge its cache tag
./manage-hints.sh --delete-key example.css
3
EdgeKV: Read → Modify → Write
Atomic update of all_hints object
# Read current object akamai edgekv read namespace group all_hints # Remove key (done in script) delete allHints["example.css"] # Write back akamai edgekv write namespace group all_hints \ --input-file updated_hints.json
4
Cache Purge (Specific Tag)
Purge cache entries tagged with this hint
akamai fast-purge invalidate \ --tag "hints-example.css" \ --network staging

Operation 3: Full Reset

5
Full Reset Operation
Nuclear option: Delete entire EdgeKV item and purge all caches using `early-hints`edge-cache-tag
./manage-hints.sh --full-reset
6
EdgeKV: Delete Item
Remove entire all_hints item from EdgeKV
akamai edgekv delete namespace group all_hints --network staging
7
Cache Purge (Global Tag)
Purge all responses tagged with early-hints
akamai fast-purge invalidate \ --tag "early-hints" \ --network staging # Purges all resources that went through hints-updater # Forces re-discovery of all resources on next cache miss
8
System Reset Complete
Result: Clean slate
• EdgeKV contains no hints
• All caches invalidated
• hints-reader falls back to static hints only
• hints-updater will rebuild hints on next cache misses
🔄 When to Use Each Operation
--show-content
• Debugging: verify what hints are stored
• Auditing: check for stale or incorrect entries
• Monitoring: routine inspection

--delete-key <key>
• Remove specific outdated hint
• Force re-discovery of single resource
• Surgical cleanup without global reset

--full-reset
• After static hints configuration changes
• After Property Manager pattern updates
• System-wide refresh needed
• Major version deployment
